# VideoHighlighter 0.12.0

The theme of this release is models people make and share. 0.11 was about where the work runs; 0.12 is about what the app can learn to find. You can now train an object detector of your own from inside the app, package it, and share it, and you can install models other people have shared. To make that possible, object detection moves to YOLOX, which is Apache-2.0, so a model trained here does not inherit a licence that stops it being shared. Around that: pose estimation returns to auto-crop, action recognition decodes on a background thread, and a clean install on Python 3.13 works again.

18 commits on main since 0.11.3.

## If you downloaded 0.12.0 early

The files on this page were rebuilt on 20 September, finished at about 19:45 UTC. An earlier 0.12.0 download could hang partway through a run with the progress bar frozen, and it had object detection switched off (`COCO labels not found`). If yours does either, download it again.

## Models you train and share

- **Object detection is YOLOX** (Apache-2.0), run through OpenVINO, or through ONNX Runtime with DirectML on AMD and other DX12 cards. There is no AGPL detector anywhere the app runs. The stock models download on first use.
- **Train a detector in the app,** from the new Train tab. You get an estimate before the run, and after the first run it is measured on your own computer. While it trains, you see the stages, the time left, and after every round what the model finds on frames it has not trained on, in a "Watch it learn" window. For now the labels come from `tools/labeler.py`; drawing boxes on the video in the app is next.
- **Share it.** After a successful run, the Train tab asks whether you want to share the model. The wizard arrives filled in from training; you add a name, a description and a category, and confirm a four-item checklist. The model is uploaded to your own Hugging Face account, which needs a write token for now.
- **A shared model carries the model, never the material.** A package is exactly `model.onnx`, a manifest and a generated model card, plus an optional licence. It is checked before upload, after download, and before use, and anything else in it is rejected. Licences are permissive only: Apache-2.0, MIT, CC-BY-4.0 or CC0-1.0.
- **Install other people's models** from Advanced → Community models…, browsed by category. An installed model is pinned to one version and appears in the object model list.
- Publishing and installing have been tested offline only. The first real round trip through Hugging Face is still to come.
- `docs/COMMUNITY-MODELS.md` explains the design and the rules.

## Action recognition

- **Frames are decoded on a background thread,** so decoding no longer waits in line with inference. On an Intel GPU a test clip went from 19.2 s to 14.8 s, with identical detections.
- **R3D + DirectML (AMD / any DX12 card)** is now a choice in the Action Recognition list. Before, the only way to get it was the Compute preference, which steers the whole run. The Auto label now names all four backends it picks from.
- **Choosing DirectML on a machine that also has an Intel GPU no longer hangs.** OpenVINO now stays on the processor when DirectML is chosen, so two runtimes no longer drive the same card.
- If the action loop does stall, it now says where. After 20 seconds without progress, the debug log records which step it is stuck in and what every thread is doing.

## Auto-crop

- **Pose estimation is back,** through RTMPose (Apache-2.0) on OpenVINO. It had been missing since the AGPL YOLO package was removed, so the people counter could never raise a count from one person to two.
- The person detector now sees the partly visible people (legs, torsos) that the low thresholds were written for. It had been filtering out every box below 40% confidence before those thresholds applied.

## Fixes

- **Python 3.13:** a clean install works again. `googletrans` pinned an old `httpx` that imports a module Python 3.13 removed, which broke CLIP and more. It is gone.
- **Subtitle translation** now uses the local language model through Ollama only. When it fails, the app says so, instead of writing an untranslated SRT that looks like a working run.
- **Trained action models** go to `models/actions/` instead of loose into the install folder. Models in the old location still load.
- **The processing time** at the end of a run is right again. It had been reporting about fifty-six years.
- **Running the tools** from a Windows console no longer crashes on the first non-ASCII character.

## Documentation

- The README is cut from 339 lines to 149: what the app does, who it is for, and how to install it, with a new "What people use it for" list.
- The detail moved to new guides, `docs/INSTALL.md` and `docs/REPORTS.md`. The composition rules and the ball-in-the-net example moved into `docs/DETECTION-GUIDE.md`.
