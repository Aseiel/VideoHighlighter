# VideoHighlighter 0.11.3

The theme of this release is making the GPU path promised in 0.11.0 work in the build people download. Since 0.11.0, on AMD and other DirectX 12 cards, the exe had quietly run detection and action recognition on the processor. That is fixed here. On NVIDIA machines, action recognition is also about 2.6× faster, because one of its models stops running on the card where it is slowest.

6 commits on main since 0.11.2.

## GPU and compute

- **DirectML works in the packaged Windows build.** 0.11.0, 0.11.1 and 0.11.2 failed every DirectML export with `DLL load failed while importing _ml_dtypes_ext`, so on an AMD or other DX12 card, detection and action recognition stayed on the processor. The bundle now carries the runtime library that export actually needs. The build now checks for that exact library, so a later update cannot silently undo the fix.
- **From source,** `onnxscript` is now a requirement. Without it, the R3D export to DirectML failed with only a line in the log, and action recognition stayed on the processor.
- **Action recognition is faster on NVIDIA cards.** OpenVINO counts any OpenCL GPU as a GPU, so its action encoder landed on an NVIDIA card, where it ran at 118 ms a frame against 40 ms on the processor. It now uses a GPU only when the card is Intel. Measured on a GTX 1060 with R3D on CUDA: 5.3 → 14.0 steps a second, with the same labels as before on 92–95% of seconds.

## Documentation

- The README lists the GPUs the app is tested on and the backend each one uses: Intel Arc A750 on OpenVINO, NVIDIA GTX 1060 on CUDA, AMD RX 570 on DirectML.
- The install instructions point at `00-VideoHighlighter-Windows-Setup.exe` instead of the older zip and `.bat`.
