# VideoHighlighter 0.11.2

The theme of this release is getting the app onto the machine at all. Until now, installing on Windows meant a zip, a `.bat` and two archive parts that had to sit in the same folder. The most common failure was forgetting the second part. 0.11.2 replaces all of that with a real installer. It also makes the highlight report say exactly which file it read.

7 commits on main since 0.11.1.

## Known issue: DirectML in the packaged Windows build

The downloaded 0.11.2 exe cannot build the ONNX models DirectML needs: the export fails with `DLL load failed while importing _ml_dtypes_ext`, and detection and action recognition run on the processor. **It is fixed in 0.11.3.** Installs from source are not affected once `onnxscript` is installed.

## Installing on Windows

- **A real installer:** `00-VideoHighlighter-Windows-Setup.exe`. Run it, click through, done. It knows which archive parts to fetch, so there is nothing to forget. It brings its own 7-Zip, so a machine without one is no longer a dead end. And it checks free space before downloading, not as a disk-full error at the end.
- It is still a downloader, not an offline installer: the build is about 2.7 GB compressed, and GitHub caps a release file at 2 GB, so the parts are fetched while it installs.
- **No administrator rights.** It installs per user, under `%LOCALAPPDATA%\Programs`, with a Start Menu entry and an uninstaller.
- The installer is named without a version, so `/releases/latest/download/00-VideoHighlighter-Windows-Setup.exe` is a permanent link to the newest one.
- The installer sorts first in the Assets list, so it is no longer lost below the multi-gigabyte archive parts.
- The installer is not signed yet, so Windows SmartScreen shows "Windows protected your PC" on first run: **More info → Run anyway**.
- The old script-based installer, `00-VideoHighlighter-Windows-Setup.zip`, stays attached as a fallback.

## The highlight report

- **The report identifies its source.** It records a SHA-256 of the whole video file with its size and modification time, the version and edition that made it, and when it ran in UTC as well as local time. A file name and a duration do not survive a re-encode or a renamed copy; a hash of the whole file does.
