# VideoHighlighter 0.15.2

A small release with one fix that matters: the written parts of the report are now told by a model you chose. Before, a run with no narration model set quietly used "llama3", whatever you had connected in the chat. The chat itself is also easier to read.

2 commits on main since 0.15.1.

## Known in this release

- **The shot list uses the simpler detector in this build.** The learned shot-boundary model (TransNetV2) is not downloaded by Setup yet, so cuts are found from frame differences. That finds most hard cuts, and fewer than the model does on fast, animated footage. Running from source with `models/transnetv2/` in place (`tools/export_transnetv2.py` makes it) uses the model.
- **Search in other languages is still English-first on Windows.** The model that reads queries in your language is not among the published packs yet. The macOS build carries it.
- **"Download and install" is not offered yet.** Only a build that carries the release signing key offers it, and this one does not.

## Narration

- **The model that narrates is one you picked.** Chapters and clips are written at the end of a run by the model set under "Models…" on the AI Summary button, which is separate from the model in the chat. With nothing set there, the run used "llama3" without saying so. It now uses the model you last connected in the chat, in the main window or the timeline viewer. With no model anywhere, narration is skipped, and the warning before the run and the log both say where to choose one.
- **A text-only model is no longer sent frames.** Ollama says which models can see, and the app now asks. A model that cannot see used to be handed the chapter's frames and refuse the whole request ("Multimodal data provided, but model does not support multimodal requests"). It now tells chapters from the transcript, and clip descriptions are skipped with a line saying why.
- **The log names the model.** Every narration starts with "Narrating with …", so the wrong model is visible before the wait, not after.

## Chat

- **A box per message.** Your message sits on the right and the answer on the left, each in its own box. The answer is in plain upright type; it used to take on the grey italics of whatever note was printed just before it.
- **The chat opens quiet.** The lines about caches, engines and the timeline connecting are in the debug log now. The line above the chat already says what is loaded. Connecting says one line, and says so plainly when no analysis is loaded for the video.
