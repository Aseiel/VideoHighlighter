# VideoHighlighter 0.13.3

Your trained action model and actions by name work together again. Since 0.13.1 a run used one or the other: with a trained model chosen, the action field still suggested the Kinetics-700 names, but any of them you typed was skipped. The Intel/R3D "mixed" mode used to run a trained model next to the Kinetics ones, and this brings that back on SigLIP2.

2 commits on main since 0.13.2.

## Known in this release

- **"Download and install" is not offered yet.** Only a build that carries the release signing key offers it, and this one does not. The update banner still tells you about new versions and opens the download page.

## Action recognition

- **A trained model and actions by name in one run.** With a trained model in use, the actions you type that are its own are scored by the model, as before, and any other typed action (a Kinetics-700 name or your own words) is scored by name beside it. One pass over the video reads each window once: the model looks at the people in it, the actions by name at the whole frame, and both land on the same timeline.
- **A blank action field is still the model's actions only,** so a run does not suddenly add every Kinetics action the video happens to show.
- **A fine-tuned model brings its own encoder,** and that one cannot read text, so the shared SigLIP2 encoder is loaded beside it, only when a typed action needs it.
- **Advanced → Action Recognition says so:** "any other typed action is scored by name beside it".
- **The two kinds of confidence are not the same scale.** A trained model's number is its own probability for that action, and an action only counts once it passes that action's trust threshold. An action by name's number is its share against the 700 Kinetics names, where 5% in a window's top three already counts. One timeline confidence filter applies to both, so a high filter hides most actions by name while the model's stay.
