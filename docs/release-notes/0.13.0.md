# VideoHighlighter 0.13.0

Teaching the app comes to the free edition. 0.12 let you train a detector from labels you had already made; 0.13 takes you from footage to a model: give it some videos and a few examples, check its guesses, and it trains, keeps improving while the app is idle, and installs a new round only when it beats the last. Around that: Windows gets a real installer with PyTorch split out into downloadable packs, a Mac can now run detection on its own GPU, and the edit can go to Resolve or Final Cut as an EDL or FCPXML, contributed by @ethiebaut.

42 commits on main since 0.12.1.

## Known in this release

- **The scoring settings show four boxes twice.** Speech, Objects & actions, Face expression and Where in the video appear a second time under the first set, and the first copy has only its buttons, no number fields. The second copy is the one that works. This has been there since 0.10 and is fixed for the next release.
- **There is no web UI download for 0.13.0.** The 0.12.1 web UI is still on that release's page.
- **"Download and install" is not offered yet.** The updater can install an update in place, but only a build that carries the release signing key offers it, and this one does not. The update banner still tells you about new versions and opens the download page.

## Teach a model

- **From videos,** the new first tab under Train. Choose what to find (objects or actions), a project, a folder of example clips and the footage, then: Check this computer, Start, Check guesses, Continue, Train. The app cuts the footage into 5-second samples, sorts them against your examples, and asks you to look only at what it is unsure of.
- **Or from one box.** Right-click an empty spot in the player, choose "Teach a model to find this", draw a box and name it.
- **Checking guesses is clicking.** The review window shows a grid of samples, each starting at the app's guess: click the wrong ones, right-click to relabel, double-click to play. Once a class has a few checked samples, guesses that clearly match are accepted without review, and every batch carries spot checks of them. If you overturn more than one in five for a class, it stops accepting for that class and hands everything back.
- **It keeps improving.** From the second round, the project's own model proposes too, and its disagreements with CLIP come first in review. Projects you opt in keep training while the app is idle; a round is installed only if it scores better than the installed one.
- **Check this computer** says in seconds whether the machine is ready and what to fix if not. Training without an NVIDIA card works, and it tells you that will take hours.
- **Share a taught detector** on the model hub with Share…, which fills in the technical fields and the project's own counts. The name, description and checklist stay yours to fill in.
- Everything the panel does is also a command (`python -m modules.teach`), each printing what it did and what comes next, so it can be scripted. `docs/TEACH-A-MODEL.md` is the guide.

## Action recognition

- **A new action backend: SigLIP2 with a head you train.** One frame encoder looks at each person in 5-second windows, and a small head trained on your own clips decides the action. On a 52-minute video it took 67 s on an Arc A750. The encoder is not a download yet, so for now this is for people who export it themselves (`tools/export_frame_encoder.py`) and train a head with `model_training.action_head`. Auto picks it up as soon as both are installed.
- **The Intel and R3D action models are marked deprecated.** They still run, and they are still what most installs use until the encoder is a download.
- **The speed line counts every frame read.** It used to show analysed frames per second, so raising the frame skip made a run faster while the number went down (frame skip 5 → 10: 21.2 s → 12.4 s, shown as 324 → 277 FPS). It now reads "Speed: 1619 fps (1 in 5 analysed)".
- The run log says in one line which action model runs on what, for example "R3D-18 on CUDA". The reasoning behind an automatic choice goes to the debug log.

## Windows installer

- **A real installer, with PyTorch as separate packs.** CUDA PyTorch was 4.4 GB of the 6.9 GB install and only changes when torch does, so it is no longer rebuilt and repacked with every release. Setup is now about 700 MB. It installs the app with PyTorch for the processor, and downloads NVIDIA acceleration and the visual search model during setup, each checked against its SHA-256. A failed or declined download still leaves an app that runs.
- **Install for me or for all users.** Per user needs no admin rights; all users goes to Program Files with one UAC prompt.
- **The NVIDIA checkbox names the card it found,** or says it found none, so you can see why it is ticked or not.
- **The portable download fetches the same packs.** The first time you pick the NVIDIA backend or visual search, the app offers the download, with a progress bar and pause, and resumes an interrupted one.

## macOS

- **Detection and R3D run on the Apple GPU** through Core ML. Before, a Mac ran every model on the processor. Set `VH_COREML=off` to turn it off.
- **The Compute setting lists only what the machine has.** A Mac was offered NVIDIA, Intel and DirectML; it now shows Automatic, Apple GPU and Processor. A PC no longer shows Core ML.

## Export to an editor

Contributed by @ethiebaut.

- **EDL and FCPXML from the edit timeline.** A CMX 3600 EDL and an FCPXML 1.9 sequence, timed on the video's real frame rate, 120 and 240 fps included, with audio events when the file has sound.
- **Markers come with the cut.** Speech, detections and faces from the analysis are written as EDL locators and FCPXML markers on the clips they overlap.
- The export dialog shows the real frame rate and how many markers it found, and lets you start the sequence at 00:00:00:00 or 01:00:00:00. CSV replaces JSON as the clip spreadsheet.

## Settings

Contributed by @orangeqoon.

- **Name the highlight file.** The output name you type is now the file name. It used to be replaced with `<video>_highlight.mp4` on every run. Leave it empty to keep that name.
- **Presets.** Save the current settings under a name, and load or delete them later. They are stored in `presets/` beside `config.yaml`.
- The tooltips on the scoring and duration controls describe what the scorer actually does.

## Composition rules

- **Rules on outlines, not only boxes.** A rule can ask whether one thing is inside, overlaps or touches another, measured on its traced outline rather than its box. Outlines are traced only where two boxes meet, and only for rules that ask for them.
- **Rules about body parts.** `person.hand` touching something is decided on the wrists, not the whole person's box. Any body keypoint works, and so do the groups hand, foot, head, knee, elbow, shoulder and hip.
- The player draws traced outlines, and the rule tables in the Advanced tab and the web UI have Relation and Outline columns. Saving rules no longer drops fields the table has no column for.

## Fixes

- **Training labels through the train/val auto-split.** When the val folder lacked a class that train had, the auto-split gave some clips the wrong class and dropped others. That affected both the training labels and the score that picks the best epoch, in the R3D and Intel trainers.
- **Pose on Intel Arc.** At the GPU's default precision every pose output was NaN, so the cropper could not confirm a person. Pose now runs at full precision on every device.
- **Auto-crop sees people again.** A lost loop left every zone counting zero people, so crops fell back to fixed positions. Crops now take a person whole, and one action stays in one crop: on 62 hand-reviewed windows, 37 of 40 single-action windows stayed whole (was 26), and two actions side by side were split in 1 of 18 (was 9).
- **DirectML on a machine with no graphics card** (a VM, a remote desktop) is no longer reported as available. The machine's adapters are now listed, and DirectML binds to a real card instead of always adapter 0.
- **The update check asks every channel** and takes the newest version, rather than stopping at the first that answers.
- **The chat panel moves between the Simple and Detailed views** without losing the conversation.
- The batch cropper no longer stops at the end to ask whether to delete the original videos, except when run from the command line.

## Under the hood

- OpenVINO 2026.4.0. Every model's output is bit-identical to 2026.2.1. YOLOX-s is about 5% faster on GPU and 5–10% slower on the processor. `docs/BENCHMARKS.md` has the measurement and how to repeat it.
- The free edition mentions Pro's 14-day trial at two moments only: when a composition rule finds nothing, and when a report lists claims this build has no engine to measure. Never at startup and never in the report itself. Each moment speaks at most once a month, and "Don't suggest Pro" turns it off. Nothing is sent anywhere.
