# VideoHighlighter 0.14.3

The theme of this release is finishing the edit somewhere else. The edit timeline now exports as a CapCut or Jianying project that appears in the app's own project list. Downloads that only work inside a browser session work again, and a long download is no longer cut off for being long. Cancel no longer crashes the next run. And the app gets a menu bar.

9 commits on main since 0.14.2.

## Known in this release

- **Search in other languages is still English-first on Windows.** The model that reads queries in your language is not among the published packs yet, so Setup does not offer it. The macOS build carries it.
- **"Download and install" is not offered yet.** Only a build that carries the release signing key offers it, and this one does not. The update banner still tells you about new versions and opens the download page.

## Export

- **Export the edit timeline as a CapCut / Jianying project.** CapCut and Jianying import neither EDL nor FCPXML, so Export Timeline has a fourth format that writes the project itself, straight into the installed app's project list: open CapCut and it is there. With both apps installed you pick one; with neither, you pick a folder to copy in by hand. Clips start and end on the same frames as in the EDL and FCPXML exports. The chat's export command takes `format=capcut` too.

## Downloads

- **Browser-session downloads work again.** 0.14.2 said Playwright was not installed and asked you to install it with pip: the build never shipped it. It ships now, and drives the Edge or Chrome you already have, so no browser comes with the app.
- **A playlist is no longer a finished download.** The browser-session step could save a stream's playlist, a few hundred bytes, as the .mp4 and report success with a 0.0 MB file. A stream that only answers the browser session that loaded it is now fetched piece by piece through that session.
- **Stopped by a stall, not by length.** yt-dlp and ffmpeg now show live progress, and a download is stopped only when you cancel it or when it has sent nothing for a while. There is no size or time limit, so an hour-long stream downloads as long as it moves. Cancel stops the tool and every process it started.

## Runs

- **Cancel no longer crashes the next run.** Cancelling during a transcript killed the worker thread after 5 seconds, inside PyTorch. The model stayed in memory, the next run loaded its own on top, and Windows ran out of memory and closed the app with nothing in the debug log. Cancel now lets the current step finish (a transcript stops at the end of its 30-second window), the log says it is still stopping, and Run waits for it.
- **Score only (no video).** The new arrow beside Run Highlighter re-scores with the current settings and writes the Highlight Report without rendering a video. Detection is cached, so on a video already analysed it takes seconds: a quick way to try a setting.
- **"Keep temp files" became "Export clips".** It keeps the same cuts under readable names. A `keep_temp` setting in config.yaml or a preset still works.

## The main window

- **A menu bar.** View holds the debug log switch (moved from the bottom bar) and the interface language. Help holds How to use, a page in English and Simplified Chinese bundled with the app, plus Check for updates and About.
- **Mentions of Pro, in a few more places.** Where Pro does something this edition does not, the app now says so: an object the selected detector has no class for, the side-by-side VR box, a recording with a camera preview beside it, and your own face categories. A "Free edition · What's in Pro?" link sits in the log header. All of it hides with the other suggestions.

## Teach a model

- **Right-click the video to teach a model, no Live overlay needed.** "Teach a model to find this" was only in the Live overlay's right-click. The plain preview takes a right-click now: pick the entry, name the thing, and the video pauses so you can drag a box straight onto the picture. A box is cut to the picture, never the black bars.

## Visual search

- **SigLIP2 only (experiment).** A fourth search engine beside CLIP only, using the SigLIP2 encoder already installed for action recognition, so there is nothing to download. It uses CLIP's prompt and negatives, so the two compare fairly on the same video. Its frame index is kept apart from CLIP's, which chapters also read.
- **The best matches come first, even at 100%.** SigLIP2 gives every clear match a score of 1.00, and CLIP often rounds to it too, so the top results came in arbitrary order. Ties now go to the frame that beat the alternatives by more. The shown scores do not change.
