# VideoHighlighter 0.15.0

The theme of this release is letting something else drive. Claude Desktop and Claude Code can run the app over MCP, and a model in LM Studio can use it from the app's own chat, with nothing leaving the machine. Intel graphics cards now transcribe and build the search index several times faster. The scan buttons say what they do and what is already saved. And the web UI download is a fraction of its old size.

16 commits on main since 0.14.3.

## Known in this release

- **Search in other languages is still English-first on Windows.** The model that reads queries in your language is not among the published packs yet, so Setup does not offer it. The macOS build carries it.
- **"Download and install" is not offered yet.** Only a build that carries the release signing key offers it, and this one does not. The update banner still tells you about new versions and opens the download page.
- **Hardware HEVC for VR is not confirmed in a headset yet,** so the new Auto render mode keeps VR footage on the processor.

## Let something else drive

- **Claude Desktop and Claude Code can use the app (MCP).** `python -m mcp_server` exposes the engine as tools: probe a video, scan a folder, run highlights, search, scan expressions, put clips on the edit timeline, and follow or cancel the work. Results carry paths, times, scores and log text, never frames or audio. Setup is in docs/MCP.md.
- **LM Studio as a local backend.** The chat, the report's narration and the advisor run on LM Studio too, and through it on any OpenAI-compatible server (llama-server, Jan, vLLM). When the chat opens it finds whichever of Ollama and LM Studio is running and switches to it.
- **A chat assistant that uses the app.** With a model in LM Studio and "Let the model use the app" ticked, the chat reads a run's report, re-runs with other settings and puts clips on the edit timeline.
- **Narration reads every frame.** Each clip was described from its middle frame only, and chapters from the measurements alone. Both now see their frames, run through OpenVINO on an Intel GPU where a converted model exists, and stop re-introducing the same person in every clip.

## Faster on Intel graphics

- **Whisper on Intel GPUs.** Transcripts on an Intel card run through OpenVINO GenAI: a 10-minute video took 28.7 s instead of 110.2 s on an Arc A750, word for word the same on clean speech. Any failure finishes on the processor. `VH_WHISPER_OPENVINO=0` turns it off.
- **The search index decodes on the graphics card.** Building the CLIP index of a 10-minute 5.7K video went from 955 s to 183 s. `compute.video_decode: cpu` in config.yaml turns it off; a file the card cannot decode falls back by itself.

## The main window

- **Scan buttons say what they do.** "Audio" and "Objects" read as labels beside their points fields. They now say "Scan audio", "Scan objects", and show beside themselves what is already saved for the videos in the list. While running, a button becomes Stop and shows its progress. With an empty list it is greyed out and says why.
- **Drop videos onto the window.** The detailed view takes videos dragged from Explorer onto the list or anywhere on the page, and the empty list says so.
- **A crash on fast scans is fixed.** Progress reports handled one inside another could overflow the stack and close the app with nothing in the log.
- **Expressions on the signal timeline.** The face scan's results are a row of their own, one lane per expression, and the Analyze panel has an Expressions button to run the scan.

## Report and advice

- **Apply the advisor's suggestions together.** Every suggestion that comes down to one setting now carries it, so the ones you tick are merged into a single re-run. Conflicting suggestions keep the stronger change and say so.

## Render

- **Auto render mode, now the default.** VR footage renders on the processor (x265), everything else on the hardware encoder. Configs that say cpu or gpu keep their choice. Hardware HEVC now asks for Main tier, which VR players expect.

## Teach a model

- **The dataset loop.** Check a hand-sorted dataset for classes with too few videos, videos that flood a class, and train/test overlap. Add a reviewed video's crops only where the dataset is thin, measure whether it helped on the dataset's other videos, and take out what measured worse. In the app (Dataset > Add a reviewed video), on the command line and over MCP.

## Web UI

- **A much smaller download.** The engine bundled with the web UI no longer carries its own CUDA PyTorch and converted CLIP. It ships like the desktop app: PyTorch for the processor in the archive, and on first start it downloads NVIDIA acceleration (only where it finds an NVIDIA card with a recent driver) and the visual search model in the background.

## Fixes

- **Saving highlights works on a video never analysed.** The first save worked; every later one refused to overwrite the entry.
- **Korean:** 31 strings that lost product names to machine translation are translated afresh.
